# Site Atlas AI plugin — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An AI agent can install Site Atlas, scan a site, advise the person with grounded recommendations stored next to the atlas, and implement the approved plan on the person's own site.

**Architecture:** Atlas gains one new record per atlas, the *advice* (`advice.json` + `advice.md`, with the site's *mode* in `site.json`), exposed through the store, HTTP, MCP and CLI, and shown on the home card and the canvas. A Claude Code plugin under `plugin/` packages the MCP server (through a launcher that finds the CLI), three commands and three skills that carry the advisory and implementation methods. The release workflow versions the plugin with the package.

**Tech Stack:** Node 24, TypeScript, Hono, Zod, `@modelcontextprotocol/sdk`, Vue 3, Vitest + Playwright; Claude Code plugin format (plugin.json, .mcp.json, commands/*.md, skills/*/SKILL.md, marketplace.json).

**Spec:** `docs/superpowers/specs/2026-10-25-ai-plugin-design.md`

## Global Constraints

- English everywhere in code, tool descriptions, skills, commands and canvas copy; `tests/english.test.ts` enforces it and must also cover `plugin/`.
- Text from scanned sites stays marked untrusted (`siteText` / `UNTRUSTED_META` in MCP, the plan's note); advice markdown written by an agent is *also* returned through `siteText`, since it quotes site text.
- Node `>=24`; no new runtime dependencies in `package.json`; the plugin launcher is dependency-free plain Node.
- Ids never change: advice and mode are keyed by the site id; `PATCH` only touches `name` and `mode`.
- Only the latest advice is kept (spec §8).
- Branch: `feat/ai-plugin`, cut from `feat/start-page` (needs `listSiteSummaries`, `SiteInfo`, the home cards).

## Review Focus

1. Advice markdown containing HTML or `<script>` from site text: the home card and the canvas panel must render it as text, never as HTML (Task 5 test with `<img src=x onerror>` in the markdown).
2. `atlas_set_advice` on a site with no scan: must fail with the "not scanned" message, not create a folder (Task 3 test).
3. A `mode` value outside `own` / `advisory` over HTTP or CLI: 400 / exit 1 with the message, nothing written (Tasks 2 and 4 tests).
4. The launcher when nothing is installed: exits non-zero with a one-line message naming `/atlas`, never hangs (Task 6 test).
5. Advice summary longer than a card can show: summary is capped at 200 characters server-side (Task 1 test), the markdown is unbounded.

**Interfaces:**
- Consumes: Task 1's store methods and `SiteMode`.
- Produces:
  - `PATCH /api/sites/:site` body `{ name?: string; mode?: 'own' | 'advisory' | null }` (at least one key) → `SiteInfo`. 400 `en.http.invalidName` when `name` is invalid, 400 `en.http.invalidMode` when `mode` is invalid.
  - `GET /api/sites/:site/advice` → `Advice` or 404 `{ error: en.http.noAdvice }`.
  - `PUT /api/sites/:site/advice` body `{ by: string (1..80); summary: string; markdown: string; mode?: SiteMode }` → `Advice`; sets the site mode when given; 400 `en.http.invalidAdvice` on a bad body or a summary over 200 characters; 404 when the site has no scan.
  - Both write routes require `application/json` (extend `takesJson` to `PUT` and paths ending in `/advice`).
  - `en.http.invalidMode = 'mode must be "own" or "advisory".'`, `en.http.invalidAdvice = 'Give by (up to 80 characters), a summary of up to 200 characters and the markdown; mode, if set, is "own" or "advisory".'`, `en.http.noAdvice = 'No advice yet.'`.
